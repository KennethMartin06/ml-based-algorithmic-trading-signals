# Presentation: Machine-Learning Trading Signals

`final_presentation.pptx` is a 23-slide, 16:9 PowerPoint deck for the mini-project viva. It is fully editable:
all text, cards and diagrams are native shapes, all charts are native PowerPoint charts, and every slide has
speaker notes. A static PDF copy is in `preview/final_presentation.pdf`.

| | |
|---|---|
| Talk length | about 17 minutes of speaker notes (~2,260 words), plus the optional live demo and questions |
| Advancing | one click per slide; slide 7 (architecture) has **two extra clicks** to reveal rows 2 and 3 |
| Needs | PowerPoint 2019, 2021 or Microsoft 365 for Morph (Windows or Mac). Older versions show a fade instead |
| Fonts | Segoe UI, Consolas, Cambria, all **embedded** in the file, so the deck looks the same on a machine without them |

## Design system

- **Direction:** dark, technical and cinematic. Deep ink background (`#0A0E14`) with a faint cool glow. One sharp
  accent, amber `#FFB547`, marks "the signal": eyebrows, key numbers and the ML series in charts. Light text
  `#EAF0F6` / `#AAB6C3`.
- **Data colours:** SPY cyan `#4CC9F0`, AAPL violet `#A78BFA`, MSFT teal `#3DDBB4`, buy-and-hold near-white,
  MA crossover slate, "reliably worse" coral `#FF6B6B`. They are the same on every chart.
- **Type:** Segoe UI Semibold titles (36 pt), Segoe UI body (14–18 pt), Segoe UI Light for big numbers, Consolas
  for labels and code, Cambria italic for equations.
- **Motif:** the amber line is the **real SPY adjusted close, 2010–2025**, the data the study used (captioned on
  slide 1). It is not a decorative squiggle.
- **Structure:** one master with three layouts (*Hero*, *Content (title only)*, *Title and content*). The footer
  and slide number live on the layouts. Theme colours and fonts are set in the theme, and the deck has six
  sections (Introduction, System, Method and implementation, Key features and live demo, Results, Wrap-up).

## Honesty rules the deck follows

- **Every number is computed from `results/metrics`** by `build_deck.py`, and the claims that depend on the data
  are guarded by assertions, so the build fails rather than printing a sentence the data no longer supports.
  Examples: "every 95% interval includes zero", "invested on every test day", "the winners change".
- **Screenshots are real.** They were captured from the running dashboard on 24 Oct 2026 (see
  `assets/screenshots/CAPTURE_NOTES.md`). The numbers on slide 16 come from that single live run, and the slide
  says so. They are not part of the reported study results, and the slide does not call that window "unseen":
  1,001 of its 1,205 test days are the study's own test period.
- **Claims are scoped to what was tested.** "Reliably" means a 95% bootstrap interval that excludes zero. Slide 18
  covers the 15 τ-rule strategies, and it discloses that 2 of the 15 argmax strategies had a higher Sharpe than
  buy-and-hold, with no intervals computed for that rule. Robustness checks are labelled as hold-out-test
  sensitivity runs.
- The synopsis' RAG stretch goal is marked **future work**, not delivered.

## How the motion was verified

See `preview/motion_report.md`. In short, three independent checks were run on the saved file:

1. **Read-back.** The saved deck is reopened in PowerPoint, which reports 4 Morph and 19 Fade transitions and
   183 entrance effects. Each slide's effects match the plan, including target shapes, triggers, delays and
   durations.
2. **File XML.** Morph is stored as `<p159:morph option="byObject"/>` with PowerPoint's own fade fallback. Every
   Morph pair shares `!!`-named objects, and every effect is in the slide's timing tree.
3. **Playback.** PowerPoint exported the deck to MP4 itself. In the extracted frames, each Morph changes
   gradually over 13–17 frames at 10 fps (≈1.3–1.7 s) instead of cutting. On slide 16 the picture's crop
   animates as well, so the cropped thumbnail opens up into the full screenshot. The filmstrips in `preview/motion/`
   show the in-between frames, the slide 1 line being drawn and the slide 7 build.

**Known limit:** series-by-series chart builds could not be applied through PowerPoint's automation interface
(it rejects them as an invalid request), so each chart wipes in as one object. You can add a "By series" build
by hand in PowerPoint (Animation Pane → Effect Options → Chart Animation) if you want one.

Before presenting, run through the deck once in Slide Show mode on the presentation machine. No automated check
replaces that.

## Quality review

The deck went through two independent review rounds, run as multi-agent workflows over the PowerPoint renders,
the slide text and notes, and `results/metrics`:

1. **Round 1:** visual, fact-check and content reviewers raised 55 findings. A skeptical verifier re-checked each
   one against the files and confirmed 27, which were fixed. Examples: slide 16 had called a mostly-overlapping
   window "unseen"; slide 17's title dropped "reliably"; the cost axis on slide 4 was not to scale; the
   walk-forward legend misdescribed early stopping.
2. **Round 2:** a confirmation reviewer found 26 of the 27 fixes resolved, and a fresh regression reviewer found
   a few new issues (an unformatted notes placeholder, double-rounded chart labels, an off-by-two day count, an
   overstated sub-line). The verifier confirmed these and they were fixed. `build_deck.py` now fails the build
   if any `{...}` placeholder reaches a slide or a note.

## Rebuilding

Run these from the project root on Windows with PowerPoint installed. `make_assets.py` needs `data/raw` (run
`python -m scripts.download_data` first).

```
python presentation/scripts/make_assets.py
python presentation/scripts/build_deck.py
python presentation/scripts/apply_motion.py
python presentation/scripts/render_preview.py presentation/final_presentation.pptx --pdf
python presentation/scripts/verify_motion.py
python presentation/scripts/build_speaker_notes.py --pdf
```

Dependencies: `python-pptx`, `pywin32`, `pandas`, `numpy`, `Pillow`, `lxml`, and ffmpeg for the video check.
No new packages were added to the project's `requirements.txt`.

## Editing

- **Small edits:** edit `final_presentation.pptx` directly in PowerPoint. Everything is native and editable.
- **Content or number changes:** edit `scripts/build_deck.py` and rerun the pipeline, so the numbers stay tied
  to the results.
- **Do not rename objects whose names start with `!!`** (Selection Pane). Morph uses those names to pair objects
  across slides 1→2, 9→10, 15→16 and 22→23 (for example `!!trace`, `!!seg_train`, `!!shot_live`).
- Registration numbers are deliberately not on the title slide. Add them to slide 1 if your department requires
  them.
